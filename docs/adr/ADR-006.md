# ADR-006: Generate OpenAPI documentation with springdoc

Status: Accepted | Date: 2026-11-17 | Supersedes: None

## Context

Consumers need an accurate machine-readable API specification and interactive documentation for all existing controllers. A manually maintained specification is an alternative but can drift from implementation. The application uses Spring Boot Web MVC. ADR-001 leaves endpoints unauthenticated; ADR-005 defines reservation listing filters.

## Decision

Use the Spring Boot 4-compatible springdoc Web MVC UI starter to generate OpenAPI at runtime and provide Swagger UI under `/api`. Document each controller operation, parameters, request and response schemas, and applicable success and error responses according to existing behavior. Add guidance to `AGENTS.md` requiring OpenAPI documentation when agents write or update controllers. Preserve existing API behavior.

## Consequences

The application gains a runtime dependency and exposes interactive documentation without authentication under ADR-001; it must not be exposed to untrusted users. Documentation must be kept in sync with controller behavior. Integration and end-to-end tests must verify the generated specification and UI, including operation coverage and representative response semantics; run `./mvnw clean verify` using Java 25.
