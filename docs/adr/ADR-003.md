# ADR-003: Close court and surface service unit-test gaps

Status: Accepted | Date: 2026-11-17 | Supersedes: None

## Context

The approved [BET-001 design](../bets/BET-001-design.md) requires service-rule unit tests, including validation, PATCH semantics and conflicts. CourtService has no isolated unit tests; SurfaceService has only a few. Existing integration and HTTP lifecycle tests provide complementary coverage. The class diagram associates each court with one surface. ADR-001's temporary unauthenticated access and ADR-002's seed behavior remain unchanged. This bounded test-and-fix work does not warrant a new BET.

## Decision

Review existing unit coverage against BET-001 and its design, prioritizing CourtService and addressing meaningful SurfaceService gaps. Add focused Maven-discovered unit tests with Mockito where useful to isolate DAOs and the mutation guard. Cover successful operations and relevant missing/deleted resources, validation boundaries, full versus partial updates, preserved fields, duplicate conflicts, surface assignment and deletion rules, and guard behavior as applicable. Assert outcomes and side effects, including no mutation or persistence on rejected requests where relevant. Fix bugs exposed by this review only when the approved design defines the expected behavior; escalate ambiguity or required design changes before implementation.

## Consequences

Focused tests complement rather than replace integration tests for persistence, concurrency and HTTP, and end-to-end workflow tests. Run relevant focused tests and `./mvnw clean verify` under Java 25, confirm test discovery and report counts and remaining gaps. Add or update integration or end-to-end regression tests when a fix affects their boundaries; report any test level not run and why. Implementation and evidence require independent Critic review and explicit Human Gate 2 approval.
